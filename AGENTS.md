# AGENTS.md

Правила работы с этим репозиторием для агентов. Подробности — в документах,
на которые здесь стоят ссылки; дублировать их не нужно.

## Что это

Кейс КРОК «Промпт-радар»: аналитика логов обращений к корпоративным ИИ-агентам.
В репозитории два слоя, и их нельзя смешивать.

| Слой | Где | Статус |
|---|---|---|
| Processing pipeline | `main.py`, `llm.py`, `clustering.py`, `zero_shot_classifier.py`, … | существующий код, менять только по явной просьбе |
| Канонический контракт | `analytics_contract/`, `analytics_export.py` | наш слой: схема, адаптер, валидатор, дашборд |

Адаптер связывает слои **файл в файл** и pipeline не запускает. Legacy-выход
(`outputs/analytics.csv`) сохраняется и не переписывается.

## Что читать перед изменениями

- `README.md` — команды запуска и устройство дашборда.
- `INTEGRATION_PLAN.md` — аудит, отображение полей `current → canonical`,
  решения по блокерам, §11 — состояние интеграции.
- `docs/metrics_catalog.md` — формулы метрик, их источники, ограничения
  интерпретации и список метрик, невозможных при текущей схеме.
- `analytics_contract/schema.py` — контракт из 30 полей, единственный источник
  истины по составу `analytics.csv`.

## Инварианты

Их нарушение — это регресс, даже если тесты не покраснели.

1. **Канонический контракт — 30 полей из `schema.py`.** Не менять состав, не
   возвращаться к одиночному `class_id`: разметка многозначная, `class_ids` и
   `class_names` — JSON-массивы, никаких разделителей через `;` или `|`.
2. **Таксономия — 31 официальный класс из `data/classes_31.csv`.** Файл
   `data/classes.csv` (10 широких категорий) и поле `scenario_id` во входных
   диалогах — legacy/demo-метаданные. `scenario_id` допустим для отладки и
   сравнения, но никогда как итоговый `class_id`. Новые категории не выдумывать.
3. **Сбой pipeline — не сбой агента.** Строки с `analysis_status == "parse_error"`
   уходят в `outputs/pipeline_errors.csv`, исключаются из
   `analytics.canonical.csv` и **не** помечаются `agent_failed`.
4. **Отсутствие `agent_failed` не означает успешно выполненную задачу.** Так и
   формулировать в любом тексте на экране и в отчётах.
5. **Ничего не выдумывать.** Нет отметки времени — нет графиков динамики. Нет
   исходного текста запроса — `summary` подписывается как резюме, а не как запрос
   пользователя. Метрики считаются из полей контракта, а не запросом к LLM.
6. **`tools` и `integrations` нормализуются по реестрам** `FIXED_TOOLS` и
   `FIXED_INTEGRATIONS` из `config.py`. Неизвестные значения не проходят молча —
   они попадают в `outputs/export_report.json`.
7. **Подписи на экране — только через `analytics_contract/dashboard/labels.py`.**
   Слой отображения не меняет данные: `unclustered` показывается как «Сценарий
   не определён», но в фильтрах, в кликах и в экспорте CSV остаётся
   `unclustered`.
8. **Тема дашборда — класс на `#viz-root`, один источник истины.** Правило
   `prefers-color-scheme` добавлять нельзя: медиазапрос не видит `theme-store`,
   и расхождение приводило к белым диаграммам и невидимой таблице. Это
   зафиксировано тестами `test_stylesheet_declares_no_os_level_theme_rule` и
   `test_theme_class_is_always_explicit`.
9. **Никаких вторых осей Y.** Проверяется тестом
   `test_no_chart_uses_a_secondary_y_axis`.

## Что известно про данные

Факты, установленные по демо-набору. При появлении настоящих выгрузок их нужно
перепроверить, а не наследовать.

- **Пригодной отметки времени нет.** `created_at` у всех 115 демо-диалогов
  укладывается в 0,64 секунды — это метка генерации, а не время обращения.
- **`tool_tokens` всегда 0**, потому что в исходных логах нет сообщений с ролью
  `tool`. Это отсутствие данных, а не бесплатные вызовы инструментов.
- **`estimated_cost` — только LLM/API-обработка** по тарифу `0,0001 за 1000
  токенов` из `token_counter.py`. Валюта в pipeline не объявлена, поэтому в
  интерфейсе единицы подписаны как условные. Это не стоимость владения системой.
- **Полей пользователя, отдела и эталонной разметки нет**, поэтому срезы по людям
  и точность классификации посчитать нельзя.
- Показатели на синтетическом наборе помечаются `DEMO / SYNTHETIC DATA`.

## Запуск

Демо-цепочка не требует GPU и не тянет `requirements.txt` целиком — достаточно
`pandas dash plotly`.

```bash
.venv/bin/python scripts/make_sample_pipeline_output.py   # синтетический выход pipeline
.venv/bin/python analytics_export.py                      # адаптер в канонический формат
.venv/bin/python -m analytics_contract.validate           # валидатор контракта
.venv/bin/python -m analytics_contract.dashboard.app      # http://127.0.0.1:8050
.venv/bin/python -m unittest discover -s tests            # 116 тестов
```

Коды выхода валидатора: `0` — контракт соблюдён, `1` — есть ошибки, `2` — файл не
найден. Дашборд не стартует на файле, который не проходит валидацию.

**Ловушка окружения.** Рядом лежит проект `nuclear-hack` со своим `.venv` того же
имени, но без `dash`. В приглашении терминала они неотличимы. Вызывать
`.venv/bin/python` по пути, а не полагаться на `activate`.

Настоящий `main.py` требует GPU и загрузки Qwen2.5-7B и на этой машине ни разу не
запускался: вся цепочка проверена на генераторе.

## Соглашения

- `outputs/` под `.gitignore`: файлы генерируемые, а синтетика в репозитории
  легко принимается за настоящие данные.
- Тексты интерфейса, README и отчётов — по-русски. Комментарии и docstring в
  коде — по-английски, как в существующем коде.
- Комментарий объясняет **почему** так сделано, а не пересказывает код.
- Новые данные класть рядом с демо-набором, не перезаписывая его.
