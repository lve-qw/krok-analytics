# **Промпт-радар: поиск метода для эффективной классификации запросов пользователей ИИ-агентов** 

**Теги** : AI Agents | Data Analytics 

# **Общее описание:** 

Разработайте инструмент аналитики запросов к ИИ-агентам. Решение должно автоматически классифицировать пользовательские запросы по типам задач, группировать их в сценарии использования, делать краткие саммари по каждой группе и формировать понятный отчёт/дашборд: что чаще всего спрашивают, какие сценарии растут и где у агента возникают проблемы.

**Проблема** (актуальность) 

Ежедневно сотрудники пишут внутренним ИИ-агентам сотни и тысячи запросов: «помоги написать письмо», «объясни ошибку», «собери отчёт», «сформулируй ТЗ» и т.д. Но бизнесу важно понимать не просто **сколько** запросов, а **зачем** люди используют ИИ и **насколько он реально полезен** . 

Когда ИИ внедрён в компанию, появляется “серая зона”: 

- запросов много, но они разнородны; 

- пользователи формулируют по-разному одно и то же; 

- часть запросов относится к рабочим процессам, часть — из интереса; 

- трудно понять, где ИИ действительно экономит время, а где создаёт иллюзию пользы. 

Ручной анализ логов занимает недели и всё равно будет субъективным. Бизнесу нужен **навигатор** , который постоянно переводит шум логов в ясные решения. 

# **Задача** 

Ваша задача — разработать систему, которая: 

- 1) классифицирует запросы пользователей ИИ-агентов (по темам/типам задач), 

- 2) находит сценарии использования (use-cases) — устойчивые «паттерны» применения агента, 

- 3) делает саммари по этим сценариям: что спрашивают чаще, какие боли, какие запросы «ломаются», где есть потенциал автоматизации. 

На выходе — понятный отчёт/дашборд для руководителей: что происходит с ИИ в компании и куда развивать платформу. 

# **Стейкхолдеры** 

CTO КРОК — они хотят: 

- видеть **эффективность внедрения ИИ** в компании (по направлениям и командам), 

- понимать **топ-сценарии** и топ-проблемы, 

- принимать решения: какие агенты развивать, какие сценарии автоматизировать, где обучить пользователей. 

Другие стейкхолдеры: 

- сотрудники компании (пишут запросы агентам), 

- владельцы платформы/агентов (улучшают агентов), 

- аналитики и продуктовые менеджеры (собирают инсайты), 

- руководители (смотрят отчёт и решают, что делать дальше). 

# **Как сейчас решают (и почему не работает)** 

- смотрят выборку логов руками, 

- считают «сколько сообщений» и «сколько пользователей», 

- ищут по ключевым словам, 

- проводят опросы. 

Минусы: долго, субъективно, сложно увидеть новые сценарии и тренды. 

# **Что будет, если не решать** 

- компания тратит деньги на ИИ, не понимая отдачи, 

- улучшения делаются «на глаз», 

- важные сценарии остаются незамеченными, 

- повторяются одни и те же ошибки пользователей → ИИ кажется «плохим», хотя проблема в формулировке/интерфейсе 

# **Ожидаемое решение** 

Система, которая превращает логи в структурированную аналитику. 

Минимальный функционал (must-have) 

# **1) Классификация запросов** 

Присвоить каждому запросу категорию (или несколько). 

_Примеры (можете придумать свои):_ 

- _генерация текста (письма, инструкции, посты),_ 

- _помощь с кодом,_ 

- _анализ данных/таблиц/SQL,_ 

- _объяснение/обучение,_ 

- _поиск/сбор информации,_ 

- _планирование/управление задачами,_ 

- _«нерабочее / общие вопросы»._ 

# **2) Поиск сценариев использования (use-cases)** 

Найти группы похожих запросов и назвать их как «сценарии». 

_Пример:_ 

- _«Написание деловых писем» → отдельный сценарий внутри «генерации текста». →_ 

- _«Объяснение ошибок Python traceback» сценарий внутри «помощи с кодом»._ 

# **3) Саммаризация по категориям/сценариям** 

Для каждой группы: что это за сценарий, зачем он, какие типовые формулировки. 

# **4) Отчёт/дашборд** 

Понятная выдача: таблица/веб-страница/презентация/ноутбук 

Например: 

- _топ категорий,_ 

- _топ сценариев,_ 

- _примеры запросов,_ 

- _динамика (если есть время)._ 

Приветствуются идеи вау-фич и экстра функционала! 

**Технологии** 

Требования к решению: абсолютная свобода выбора решения/технологии. Ограничение по использованию GPU (H100) 

**Критерии оценки** (на что обращаем внимание) 

- 1) Понятность результата для CTO: отчёт должен отвечать на вопрос «что 

происходит и что делать дальше?» 

- 2) Качество группировки: похожие запросы действительно вместе, разные — разделены 

- 3) Интерпретируемость: категории/сценарии названы понятно, есть примеры 

4) Техническая реализация: устойчивость, воспроизводимость, скорость 

5) Креатив/продуктовость: фичи, которые превращают анализ в полезный инструмент 

# **Формат сдачи** 

- репозиторий с кодом + инструкция запуска 

- входной датасет (или скрипт генерации/загрузки) 

- итоговый отчёт (md/pdf) или дашборд (Streamlit/Gradio/веб)
